# 灵基 Build 评测功能详细验收清单 v1.0.0

版本：v1.0.0｜产品阶段：MVP｜配套正文：[评测功能需求文档 v1.0.0](02-灵基Build评测功能需求文档-v1.0.0.md)

本文包含 59 项功能验收场景（A01–A59）、12 个澄清样例（C01–C12）、9 项接入前置事项（T01–T09）和 6 项判定质量校准检查（Q01–Q06），覆盖技能与智能体。F01–F16 对应配套正文的同编号功能。以下条目为验收要求，不预填通过结论。

## 一、验收方法与记录要求

技能和智能体分别按“对象入口 → 准备用例 → 运行 → 查看证据与报告 → 对话修改 → 检查修改结果 → 手动重跑”验收。准备阶段包含对话生成；修复须验证失败证据传入原对象开发对话，修改直接写入原对象。测试应核对用户可见行为、保存内容、证据，以及历史记录是否保持不变，不依赖组件内部变量、样式类名或模拟计时。

- 浏览器流程：核对入口、选择范围、表单、离开确认、一次性加入及防重、导航、报告下载、修复返回及删除阻断。
- 现有服务层回归：复用快照、文本匹配、点数、报告、一次性加入及删除测试，检查外部输入输出和恢复后的行为。
- 真实联调：沿同一流程核验模型、MCP、澄清、取消、判定重试、会话与工作区隔离、对象内容固定、点数查询。

原型交互、模拟测试和真实环境的通过结果分别记录。不能只看页面是否显示“通过”，还须核验输入、执行、标准和证据。不能因为当前执行环境能力不足，就缩减实际需要支持的范围。

验收每一项时，记录验收层次与环境、对象及内容标识、用例／运行编号、操作或触发条件、实际结果、证据链接、结论及问题编号。未执行的标“未执行”，存在环境或能力缺口的标“阻塞”，不得填“通过”。

## 三、固定澄清样例

C01–C12 覆盖支持的澄清类型、匹配、提交和异常处理；C09 依据已确认的系统规则验证次数边界。须核验真实待答请求、答案提交和接收记录，不能用界面中的模拟问答证明能力。未匹配或发生异常时，终止当前用例，后续轮次标为未执行；其他用例继续，用户停止整次运行除外。

| 编号 | 输入或触发 | 预期结果 |
| --- | --- | --- |
| C01 | 配置“核算组织 → 华东公司”，实际自由文本问“此次查询属于哪个公司？” | 按含义唯一匹配，提交华东公司，确认接收后记录已回复 |
| C02 | 实际单选为华东／华南公司，配置回复华东公司 | 映射到一个真实选项；不允许自定义时不得发送选项外文本 |
| C03 | 实际多选查询维度，配置明确选择“客户、物料” | 转为对应多个选项；存在无效选项则不提交 |
| C04 | 一次请求含组织和期间两题，两项都有配置 | 按题目顺序统一提交，整批只算一次独立请求 |
| C05 | 同批询问组织和仓库，仅组织有配置 | 整批不提交，组织显示已匹配未提交，仓库显示未匹配，终止当前用例 |
| C06 | 一句话“请确认组织及查询月份”，两项配置明确 | 拆分事项并组合完整答案；存在不能明确拆分的表述时不猜测、不提交部分答案 |
| C07 | 实际问题无配置，或有两个无法区分的匹配配置 | 分别显示未匹配／匹配歧义，结束待答并终止当前用例，其他用例继续 |
| C08 | 同一个请求重复通知，随后新发起同内容请求 | 重复通知不重复提交、不计数；新请求再次匹配并新增计数 |
| C09 | 单轮请求达到系统允许次数后仍发生新的独立请求 | 允许范围内可回复；超限请求不回复，记录原因并终止当前用例，其后轮次未执行；另用未超限的多轮用例验证每轮独立从零计数 |
| C10 | 答案提交失败，或发送后无法确认接收 | 不显示已回复，保留拟提交答案与失败／未知原因，终止用例；不能盲目重复发送 |
| C11 | 实际请求登录、授权或选择服务来源 | 不使用业务澄清配置回答，记录环境或授权待处理及影响 |
| C12 | 执行环境不能识别待答请求或处理某受支持题型 | 明确记录能力限制、未执行轮次和无法判定原因，该场景不得验收通过 |

## 四、接入验收前置事项

本版不规定名称、用户输入、正则辅助字段的固定字符数，也不规定附件的固定容量。正式服务若需要限制，应在接入前记录业务或平台依据、适用范围和用户提示，并同步正文与本清单；不能直接把原型常量当作产品要求。

分页条数属于展示参数，验收按当前页面数量准备数据；近 7／30 天是快捷筛选选项，全部时间与自定义范围仍可使用。必填、至少一轮及至少一条评测标准是用例成立的必要条件。澄清和判定重试都不能无限执行。具体次数与时间参数的依据在接入前确认，本清单不预设数值。

## 五、原型证据与真实验收的区别

当前原型使用本地数据和模拟执行，未连接真实模型、评测引擎、MCP 或 ERP。页面可操作、模拟测试通过，均不能证明真实接入完成；草稿加入的跨记录事务、服务端持久化及修复内容保存仍须由正式服务验证。

各能力的模拟方式、存储限制和待接入事项见[原型说明](../docs/evaluation-mvp-prototype.md)。原型检查与真实验收按第一章分别记录，不能互相替代。

## 六、判定质量校准检查

本节用于确认“判定是否可信”，不增加产品中的评分、看板或人工复核功能。校准对象是冻结的“单条标准＋其允许读取的执行证据”，先验证判定器，再做真实端到端运行；业务数据变化不能混入固定证据的重复判定实验。

| 编号 | 检查方法 | 应留存的证据 |
| --- | --- | --- |
| Q01 | 业务人员与测试分别标注预期结论及依据，再核对分歧。覆盖通过、不通过、无法判定、不适用，以及条件不明、工具失败但回复声称成功、空回复／缺失回复、缺少附件内容等边界。人工结论未收敛的样本单列，不悄悄删除或计入一致率分母 | 样本版本、对象类型、标准、证据、两份人工标注、分歧及最终依据；各类型样本数和排除原因 |
| Q02 | 冻结判定模型、提示与规则版本，对同一批证据判定；按标准类型、预期结论和对象类型分别统计，不只报告一个总体比例 | 每项人工／系统结论、差异原因；一致率＝相同结论项数／有人工定论项数；输出缺失或格式无效计为不一致 |
| Q03 | 单独检查误放行：人工不通过、无法判定或不适用，却被系统判为通过；关键反例包含工具失败冒充成功、证据缺失冒充通过和读取后轮证据。原有禁止误放行的功能约束继续按 A17、A19、A21–A23 验收 | 各人工结论组的误放行数／样本数；关键反例逐项记录。不能用其他通过项抵消关键错误 |
| Q04 | 核对解释是否引用允许范围内的真实证据、是否正确定位差异、是否编造工具成功或已读文件 | 证据引用正确项数／已检查的有效判定项数；缺少应有依据计为错误；另列输出无效项，不因无效项不入此分母而将其忽略 |
| Q05 | 对同一标准与固定证据重复判定，保持模型和规则版本一致；不重复调用业务工具 | 每次判定与版本；稳定率＝全部重复结论一致的样本数／重复样本数；任一次输出无效计为不稳定 |
| Q06 | 用未参与调试的保留样本核查判定结果与人工结论是否一致；再沿真实执行链验证证据采集、判定与报告一致。修正规则后重新检查受影响样本，保留原结果 | 保留样本结果、真实运行与报告链接、变更前后结果；技能／智能体及各支持执行环境分别记录 |

分母为零时显示未覆盖，不计为 100%。本节中的一致率等是质量检查指标，不改变产品“不设权重或分值”的规则。

## 七、交付通过条件

- 技能和智能体分别完成第一章的完整流程及 A01–A59、C01–C12 中适用场景；修复后须检查原对象产物卡片，再返回原运行手动重跑。
- 核心正常流程和异常场景均有可复查证据，结果、报告、点数及历史快照口径一致。
- 完成正式支持的澄清类型、真实任务停止、判定重试、会话与工作区隔离、对象内容固定及点数查询的联调验证。
- 对外宣布完成前，须完成本清单第四章中的必要接入事项。无法支持的必需场景应记录为未完成，不能靠隐藏入口或将结果改为模拟通过来完成验收。
- 按 Q01–Q06 提供真实校准记录；原型固定结果不计入判定质量。
