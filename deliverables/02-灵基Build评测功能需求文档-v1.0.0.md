# 灵基 Build 评测功能产品需求文档

版本：v1.0.0｜产品阶段：MVP｜更新日期：2026-11-02

## 一、需求概述

帮助技能与智能体开发者保存和复用业务用例，核查过程与结论，将失败证据带入原对象开发对话，修改后手动复测。

## 二、背景与目标

单次测试难以覆盖多轮追问、信息缺失、附件、工具异常和产物交付，也难以复查修改前后的差异。本版要让业务场景可复用、每项判断有依据、历史记录可追溯。执行是否完成、业务是否达标必须分开说明，不能把环境异常、证据缺失或判定失败一概标为业务不通过。

| 目标 | 验证方式 | 验证要求 |
| --- | --- | --- |
| 可重复完成业务验证 | 技能、智能体分别在真实环境完成准备、运行、证据查看、报告和重跑；包含一次性加入生成草稿与复用开发对话的修复回流 | 发布前完成 A01–A59、C01–C12 中适用场景 |
| 结论可信、依据可复查 | 用人工确认的标准与固定执行证据校准语义判定，检查结论一致性、误放行、证据引用和重复判定稳定性 | 方法见验收清单 Q01–Q06，发布前形成真实校准记录 |
| 减少重复准备和整理材料的工作 | Beta 试用中比较同一业务场景手工整理与使用评测的准备、复测和报告整理用时，并记录不能独立完成的环节 | 只记录试用结果，本版不新增效果看板 |

当前没有可用于承诺节省比例或语义判定准确率的实测基线。不将原型示例的通过率当作产品效果。

## 三、目标用户与价值

本功能仅面向技能与智能体开发者。

| 用户 | 要完成的任务与现有困难 | 产品提供的能力及价值 |
| --- | --- | --- |
| 技能与智能体开发者 | 需要验证业务要求是否满足、确认修改是否改善效果；临时提问、反复手动操作和整理材料难以保持场景一致，也难以追溯差异 | 保存和复用用例，查看结果、依据与报告；携带失败证据进入原对象的开发对话，通过开发对话修改，再手动重跑验证，减少重复准备、描述问题和整理材料的工作 |

## 四、用户场景与交互流程

| 场景 | 用户操作 | 应获得的结果 |
| --- | --- | --- |
| 开始评测 | 从技能或智能体卡片、详情进入 | 确认对象和环境，查看该对象的用例及记录 |
| 手动准备 | 填写多轮输入、附件、澄清回复和标准 | 保存一条完整、可运行的用例 |
| 对话准备 | 描述业务场景，审阅和修改生成草稿 | 审阅后一次性加入，加入后统一在用例列表维护 |
| 选择范围 | 运行全部用例或跨页勾选 | 明确本次运行数量和范围 |
| 处理异常 | 查看阻断原因，必要时停止 | 知道哪些已完成、哪些未执行及下一步处理方向 |
| 查看结果 | 从运行进度定位用例，查看标准详情 | 核对实际回复、工具结果、澄清及判定依据 |
| 留存报告 | 预览并下载报告 | 获得可独立打开、可复查的当次评测材料 |
| 查看消耗 | 查看自动更新的点数 | 查看本次运行总量，分清统计中、完整、不完整或暂未获取 |
| 对话修改与复测 | 通过开发对话修改原对象，检查修改后返回原记录重跑；用例问题可先调整用例 | 使用最新保存内容形成新记录，保留旧依据 |
| 清理数据 | 删除用例或被测对象 | 先确认影响范围，避免误删关联数据 |

主流程：进入评测 → 保存用例 → 选择运行 → 查看过程与结论。之后按需查看报告，或携带失败证据进入开发对话修改原对象，检查修改后手动重跑。对话生成与对象修复均为可选操作，不自动触发评测。

## 五、功能需求与业务规则

### F01　评测入口与对象范围

技能和智能体的卡片菜单、详情页提供“评测 Beta”入口。工作区显示对象名称、运行环境，以及“评测用例”“运行记录”两个视图和对应数量。普通入口打开用例列表。直接访问、刷新或使用浏览器前进后退时，应保持当前运行、该运行内的用例结果或报告位置。从详情返回时，应逐级回到用例、运行或对象列表。

仅评测列表中已有对象，内置技能需先导入。数据按用户和对象隔离，同名对象不能混用；对象不存在、已删除或不可访问时说明原因并禁用相关操作。生成及修复会话进入对象所属项目，项目不可用时留在当前页提示恢复，不进入其他项目。

### F02　用例列表与批量选择

用户可以按名称搜索并分页查看；搜索忽略大小写和搜索词首尾空白。列表支持单选、全选所有用例（跨页）、跨页保留选择及取消选择，显示选中总数，并分别标明搜索结果外和搜索结果中其他页的已选数量。修改或清空搜索条件后回到第一页，保留已选用例；搜索无结果时也保留。“全选”选择当前对象的所有用例，包含其他页及搜索结果外的用例；取消全选或“取消选择”均清空全部已选用例。全选框按全部用例显示未选、部分选中或全选状态，仅在当前对象没有用例时禁用。“运行所选”包含当前不可见的已选用例，按钮数量与实际运行范围一致。

无选择时运行对象全部用例，有选择时只运行所选。搜索不会缩小“全部运行”的范围，按钮应显示总数并提示包含搜索结果外的用例。无用例时禁止启动；无搜索结果与尚无用例使用不同提示。点击名称先进入只读详情，再按需编辑。

删除一条或多条用例前，须说明操作不可恢复、历史记录仍保留，并请用户确认。取消不改变数据；删除失败时保留选择并提示重试，不显示成功。

### F03　手动创建与编辑

| 内容 | 规则 |
| --- | --- |
| 用例名称 | 必填，不能仅为空白，保存时去除首尾空白 |
| 对话轮次 | 至少一轮，可新增、排序、折叠、删除，不能删除最后一轮 |
| 每轮用户输入 | 必填，不能仅为空白 |
| 澄清回复 | 可不配置；添加后预期追问与自动回复均必填，可配置多组 |
| 评测标准 | 全用例至少一条轮次或整体标准；每条已添加标准均须完整有效 |

删除轮次同时移除该轮输入、附件引用、澄清和标准，操作前确认；删除已有内容的标准或澄清回复需确认；误加的空白项直接移除。编辑中的删除在保存用例后生效。单轮可以不配置标准，但整个用例仍须至少有一条标准。

校验失败应展开并定位首个错误字段，说明如何修改。任一附件正在上传时禁止保存。保存、取消、离开提醒及保存失败处理遵循 F16。

### F04　对话生成与草稿确认

用户选择“对话生成”后，进入对象所属项目的会话。会话预填为当前对象生成用例的请求，由用户发送。用户可描述场景和预期结果、补充材料或继续对话。需求明确时直接生成，意图不明确时先澄清，不将无关输入变成标准。

生成结果先以草稿展示，用户可预览、编辑未加入草稿，再选择一次性加入用例列表。用户指定修改未加入草稿时，应保留其他内容；增加轮次不覆盖已有输入、附件、澄清和标准。生成不自动加入列表或启动运行。草稿编辑的离开提醒遵循 F16。生成期间禁止编辑或加入草稿；有未保存的编辑时，先保存或取消，再继续对话。停止生成或会话中断时，保留此前已完成的草稿，允许继续处理。

草稿只区分待加入和已加入。用户审阅后一次性加入正式列表；成功后保留加入时的草稿供查看，关闭该草稿的编辑、对话修改和重复加入入口，提供“前往用例列表”。后续统一在用例列表维护，不再比较、同步或覆盖正式用例；正式用例被修改或删除，也不能从原草稿重新加入。批量加入前检查全部待加入内容，任一无效则整批不加入；加入只新增用例，不覆盖已有用例。只有保存成功后才标记已加入；失败保留编辑内容、草稿、选择及原用例，说明原因并允许重试。重复操作不能新增重复用例，历史记录保持不变。

### F05　输入附件

会话附件在用例开始时提供，本轮附件随对应输入提供，不能提前使用后轮材料。用户应看到上传状态和失败原因，失败可重试；详情与结果支持下载输入附件，读取失败说明原因。

从当前用例移除附件，不影响历史运行仍在使用的附件。输入材料不能当作生成产物；只有文件名，不代表内容已被读取。只有实际读取并保留的内容，才能作为判定依据。本版不自动检查产物内容，也不提供产物下载。

### F06　标准配置

轮次和整体都可添加多条标准，支持以下四类：语义判断，用自然语言描述业务要求、条件和预期；关键词匹配，选择包含全部、包含任一或不包含任一；正则匹配，检查指定格式匹配或不匹配；文件存在性，检查指定产物路径存在或不存在。

所有标准都影响结论，失败项不能被忽略；不设权重或分值。预期答案并入语义描述，不另设参考文件。关键词支持添加、移除和去重，去除首尾空白并保留内部空格。

正则可手动填写，也可描述格式后辅助生成；用户查看解释、输入示例验证后确认使用。修改描述使旧生成结果失效。表达式无效时不能保存；格式符合要求，不代表业务数据真实。文件存在性标准须填写当前用例产物区域内的相对路径，不允许绝对路径或跳转到区域外。

### F07　检查范围与结论

**检查范围。**轮次语义判断在本轮正常结束后查看截至本轮的实际输入、澄清、工具调用及返回、最终回复；前轮内容只用于理解上下文，不读取后轮内容。整体语义在全部业务轮次正常结束后检查完整过程。每条结论应指向实际证据并解释差异，对象声称已完成不能代替外部业务成功依据。

关键词和正则只检查本轮最终回复，整体只检查最后一轮回复，不混入输入、澄清、工具或文件内容，也不以前轮回复替代。文件在本轮结束、下一轮开始前检查，整体在最后一轮正常结束后检查；记录期望路径、实际路径、检查时间和结果，后轮修改文件不改变前轮结论。“不存在”也须完成检查；超时、不可访问、未到检查时点或证据缺失均无法判定，不能用停止后的状态替代。

**文本规则。**检查时保留回复中的大小写、空格及排版标记，只统一不同换行符。关键词区分大小写，按字面包含判断，因此“完成”会匹配“未完成”；业务含义应使用语义判断。正则默认区分大小写，不自动开启跨行匹配或逐行开头结尾匹配；找到符合格式的片段即匹配，要求全文符合时须在表达式中明确。填写表达式本身，不附两侧分隔斜杠或额外模式，示例验证与实际检查使用相同规则。明确记录为空的回复可检查，未记录回复一律无法判定，否定匹配也不例外。

**结论规则。**任一适用标准不通过，用例不通过；无失败但存在无法判定、全部标准不适用或执行不完整，用例无法判定；执行完整且全部适用标准通过才通过。不适用只用于带明确条件的语义标准，并须有证据证明条件未发生；条件不明则无法判定，其他标准不能不适用。

**执行与判定。**标准不通过不阻止后续业务轮次。判定超时或无效可按系统规则有限重试，只重新判断已有证据，不重复业务操作；重试结束仍失败则无法判定，已完成的业务状态保留。执行异常或停止后，不再开始新的整体判定，也不用部分证据补判。保留已有结论；未完成的标准说明原因并标为无法判定。停止同时取消未完成判定及重试，结束后补到的结果不得覆盖已确认结论。

### F08　业务澄清与自动回复

只有被测对象实际等待用户回答时才使用澄清回复，普通疑问句不触发。只使用当前轮次的配置，根据问题含义、上下文、选项和约束寻找唯一匹配，不要求文字一致。没有匹配或存在歧义时不猜测，也不编造配置外的业务事实。

支持自由文本、单选、多选、一次多题及可明确拆分的一句话多事项。题型以实际提问为准，单选对应一个选项，多选对应一个或多个选项；只有允许自定义时才能回答选项外内容。多题或多事项须全部匹配且符合要求，按提问顺序一并提交；任一项失败不提交部分答案，其他已匹配项显示“已匹配，未提交”。

自动回复须限制次数，避免无限追问。每轮按独立请求计数，一批多题算一次。同一请求重复通知不重复回答或计数，新发起的相同问题仍计数，同一配置可重复使用。达到系统允许的次数后，新增请求不再自动回复，说明原因并终止当前用例；下一轮重新计数，本版不增加用户配置项。

确认答案已被接收后，才能显示已回复。未匹配、歧义、选项冲突、无法拆分、超限、提交失败或接收不明、环境授权待处理、无法处理请求时，应说明原因，结束待答及当前用例，后轮未执行，其他用例继续。登录、授权、服务来源选择不能自动回答。配置未使用不直接判失败，是否应追问由标准检查。

配置与实际过程分开展示。每次请求逐题记录问题、必要上下文、题型、选项、匹配配置、拟答、提交结果及异常；重复通知不新增过程记录。

### F09　开始运行与历史依据

启动前应确认对象可用、有用例可运行、环境为沙箱，且同一对象没有活动评测。生产环境或环境未知时，不能启动或重跑；已有活动评测时，提供“查看当前运行”，不再新建运行。

评测沿用对象上下文中的租户源、第三方源、个人源 MCP，不新增用例级来源选择或评测专用读写权限划分；实际调用仍遵守 MCP 自身权限与授权结果。拒绝、失败和超时按实际结果记录。

每次运行有独立编号，保留所选用例及顺序、输入、标准、澄清、附件、判定规则、环境，以及被测对象当次最新已保存内容的标识或摘要。本次执行始终使用启动时确定的对象和用例内容，期间修改或删除用例不改变当次依据。不同运行、不同用例的对话和文件互不影响，同用例各轮共享前文及产物。

每次运行须留存运行开始、结束时间，以及每个已开始用例的执行开始、执行与判定结束时间，并关联当次运行和用例。时间取自实际执行过程，刷新或重新进入页面不能重新计时，结束后不能因查看记录或生成报告改写时间；重跑另建记录。未开始用例不补写起止时间，历史缺失数据不按轮数、当前时间或其他用例推算。

只有本轮业务正常结束并保留实际结果后，才进入下一轮。等待澄清或提交答复，都不代表本轮已经结束。离开页面不会自动停止，重新打开仍查看原运行。用例不单独选择工具服务来源或环境。

### F10　运行状态与停止

运行中、判定中、停止处理中、停止待核实均属于活动状态；同对象不能再次启动或重跑，当前运行不能修复或生成最终报告，对象不能删除。业务已结束但仍在判断标准时显示判定中，不提前显示已完成。运行中及判定中可请求停止。

点击停止后先显示停止处理中，并停止业务、待答、判定和重试。只有确认全部结束才显示已停止；无法确认时显示停止待核实，刷新后仍保留限制，不能仅因等待较久就允许重跑。整次运行发生故障时，也须确认所有任务均已结束，才能将其标为执行异常并结束运行。

执行状态与业务结论分开：未开始的轮次为未执行，进行中被中断为已停止，仅判定被取消不改变业务已完成。保留已有证据和明确失败，其他标准无法判定并说明原因。单个用例工具不可用、被拒绝、连接失败、超时或澄清阻断时终止该用例，其他用例继续；停止整次运行除外。异常需说明发生阶段、原因和处理建议。

进度显示已处理的用例数。仍在判定的用例不计入完成数；无法判定、已停止、未执行的用例可计入已处理数，但不能计为通过。“已完成”表示流程结束，不表示全部业务要求满足。

### F11　运行记录与结果详情

运行记录按开始时间倒序分页，展示时间、状态、用例数、通过数、整体耗时和消耗点数，支持快捷日期及自定义范围筛选。日期范围包含结束日，起始日期晚于结束日时提示错误；修改筛选后回到第一页。记录标题与查看结果入口进入同一运行详情。进入详情再返回列表时保留筛选条件。

状态筛选默认“全部状态”，提供四类选项：进行中（执行中、判定中、停止处理中）、已完成、已停止、异常（执行异常、停止待核实）。状态与时间条件同时生效，先筛选后分页，分页数量按筛选结果计算；无匹配记录时显示空结果提示。列表保留具体运行状态，不以筛选分类替代；“已完成”仅表示运行结束，不代表用例全部通过。筛选分组不改变原有状态含义或操作限制，停止待核实归入异常仍须等待终止确认。

界面和报告的指标名称统一显示“耗时”，通过所在的运行或用例位置区分。运行记录列表仅展示运行级摘要和整体耗时，不提供用例明细展开入口；运行详情总览展示整体耗时，用例结果行及单用例详情展示对应耗时。

整体耗时从运行开始至全部执行与判定结束，包含等待时间；单用例耗时从该用例开始执行至执行与判定结束，包含多轮交互、澄清及判定，不包含开始前的排队等待。整体耗时不按各用例耗时求和。运行中、判定中、停止处理中和停止待核实时持续计时，显示“计时中”；已结束用例的耗时先行固定，不随其他用例继续增长。运行正常结束、确认停止或确认异常结束后，整体耗时固定。

待执行和未执行分别显示“待执行”“未执行”。历史缺少必要起止时间或时间无效时显示“未记录”，不显示负数、不将缺失当作零；只有记录确实为零时才显示“0 秒”。各处使用一致的时间单位及精度，具体格式见原型说明。刷新后沿用已留存时间，重跑生成新计时记录，不改写旧记录。

运行详情展示对象、环境、当次版本、各类结论数量和进度。用户可定位用例，逐轮查看输入、附件、澄清配置与实际过程、工具记录、最终回复及标准；整体标准单独展示。每项标准提供实际结果和判定依据，文件检查另提供路径与检查时点。

不通过和无法判定的用例直接展示问题摘要，优先呈现明确失败及发生位置，否则说明异常、停止或证据缺失原因。摘要取自当次记录，与详情和报告一致，不重新判定；通过和待判定用例不显示问题摘要，完整问题通过详情查看。

空回复、未记录回复、未执行和待判定须区分。历史信息缺失时明确说明，不用当前值补写；当次判定规则按 F09 留存，不要求在详情或报告中单独展示通用规则。

### F12　评测报告

运行结束或确认停止后，可预览、下载最终报告。报告围绕评测结论、问题清单、用例概览和详细结果组织，包含对象及当次版本、运行信息、整体耗时、单用例耗时、逐轮及逐项证据、运行级消耗点数与统计状态，内容与当次结果详情一致。整体耗时在报告标题区直接展示，单用例耗时在用例概览及详细结果展示，预览与下载口径一致。问题清单概括异常原因，用例概览展示全部用例状态，详细结果提供完整过程和证据，避免重复展示。停止、异常、不完整或无结果不得表述为全部通过，不增加无数据依据的评分或指标。

报告支持连续阅读、按章节及用例定位、用例和轮次的批量展开／折叠；长名称可完整查看，目录宽度可调整。预览与离线下载保持内容及主要交互一致。报告不单列通用判定说明，历史判定规则仍随运行记录保留，用于追溯。具体布局与交互样式见原型说明。

报告只展示附件信息，不打包原文件或产物；用户文本不得作为脚本执行。已下载报告保留下载时的内容与点数状态，系统更新后需重新下载才能更新文件。

### F13　消耗点数

页面与报告统一使用“消耗点数”，首版仅展示本次运行的总量及统计状态，不展示逐用例、逐轮或执行／判定拆分明细。总量应覆盖本次评测运行产生的计费消耗，包括执行、判定等实际计费环节；只取得部分环节时须标明统计不完整，不能以执行点数冒充完整总量。生成用例及修改对象的消耗沿用开发会话统计，不并入评测运行；重跑归属新运行，不累加到旧记录。须区分实际零点数、未知和部分已知点数，不以估算成本代替实际记录。

点数由系统自动更新，不提供“刷新点数”按钮。运行期间自动查询，结束后继续有限补查；达到重试上限后停止本轮查询，重新打开未完整的运行记录时自动检查并更新。只查询点数，不新增运行、不重新判定或重复业务操作；并发查询去重。查询失败或暂未完整不影响查看结果、修复与重跑。

点数展示区分完整、统计中、统计不完整和暂未获取；部分已知时同时显示已获取总量与统计状态。未知不得显示为零，统计更新时间不代表结算完成，不展示内部计费标识。

运行总量、完整性及最近成功更新时间一起更新；失败保留已有值和时间，不用本次失败时间替代成功时间，也不拼接不同查询结果。刷新页面后中断的查询可自动恢复。运行记录、运行详情与在线报告使用同一运行级统计。下载文件的更新规则见 F12。

### F14　重新运行与技能、智能体修复

支持按原运行全部用例、明确不通过用例或单条不通过／无法判定用例重跑，并明确范围及数量。不通过范围与修复问题一致，不含无法判定；没有不通过用例时，该范围不可运行。

重跑使用所选用例与对象最新已保存内容，遵守 F09–F10 的环境及活动运行限制，生成新记录，不改写旧记录；未保存编辑不参与执行。正常范围选择后直接启动；所选范围内部分用例已删除时，列明缺失与剩余范围并确认，全部删除时禁止重跑并引导返回用例列表。

技能和智能体均支持携带证据进入现有开发对话：对象仍存在且可编辑、运行已结束并有明确不通过时，提供“修复问题”或“去修复”。对象不可编辑、活动运行、全部通过或仅无法判定时说明不可修复原因。针对整次运行修复时，携带全部失败用例；针对单个用例修复时，只携带该例。请求先预填，由用户确认发送，再在原对象的开发对话中分析问题并修改；附件只传名称和引用，不假定内容已读，历史证据仅作为问题材料。

修复绑定原对象类型、标识、所属项目和来源运行，重新打开会话后仍保持关联；同名对象或提示内容不得改变目标，目标失效时停止，不创建或修改其他对象。先核对当前内容与评测时的差异，区分对象缺陷、用例要求、数据变化和环境问题，只修改已确认属于当前对象且可编辑的内容，不能为了通过而放宽标准。智能体修复不默认改写关联技能或知识源。

对象定位、修改保存和产物展示复用现有开发对话能力，修改按现有机制保存，无需另行保存。评测负责传递失败证据、绑定来源和提供返回入口，不维护独立修复状态或判断修复完成。用户检查修改产物后返回原运行，单例来源定位对应结果，再手动重跑验证；不自动提交、发布或复测。

### F15　删除对象与数据保留

删除用例保留历史运行。删除技能或智能体时，永久清理其用例、运行、报告与点数记录、编辑及生成草稿、评测生成和修复会话、消息及返回关联，并清理不再被其他评测使用的专用附件。其他对象、普通开发会话和仍被引用的附件不受影响；已下载报告无法撤回。

确认删除前，应说明完整影响范围和不可恢复性，取消不改变数据。有活动评测，或相关会话仍在生成、等待回答时，禁止删除，须先停止并确认结束。批量操作中任一对象不满足条件，整批不删除。保存或附件清理失败不显示成功、不移除对象，允许重试；删除成功后，刷新页面或访问历史链接都不能恢复入口，应显示已删除或不存在。

### F16　通用交互要求

表单应说明必填项、可选项及澄清自动回复的用途。空列表、不可操作和操作失败应说明原因与下一步；删除和放弃修改使用一致的确认方式。状态不能只靠颜色，主要操作可通过键盘和辅助技术完成，焦点与错误位置清晰可辨；长文本、长路径和窄屏下仍可正常阅读和操作。具体展示方式见原型说明。

原型演示须明确标识，与正式能力区分；示例结论须有对应证据，修正示例不改写历史运行。模拟方式及检查细节见原型说明，不能替代真实验收。

手动用例和生成草稿的编辑均遵循以下规则：保存或取消后返回进入编辑前的页面；有未保存修改时，离开、关闭或刷新须提醒，用户可继续编辑或确认放弃。保存失败时保留内容和选择，持续显示错误，不显示已保存或已加入。

## 六、MVP 范围与边界

MVP 覆盖 F01–F16 所述的用例准备、评测、报告、运行级点数、重跑及修复回流；对话生成和修复由用户按需使用。关键异常须说明结果和后续处理方向。

不包含自动改进、候选副本自动采纳、自动复测或发布；不增加用例分类分级、回归标签、总分权重、工具参数断言、独立参考文件、产物内容检查和下载。无全局评测菜单、独立对象版本平台、额外协作权限矩阵或跨设备同步。不做生成草稿与正式用例的双向同步、差异比较、冲突覆盖或删除后重新关联；不新增独立修复编排或“修复完成”判定；逐轮、逐用例、执行与判定拆分的点数展示后移。

仅允许沙箱评测，不提供生产环境例外或用例级工具来源选择。并发、超时、判定重试及澄清上限采用系统规则，不增加高级设置。复杂澄清的扩展展示、效果看板和报告附件打包不在本版范围；基本澄清过程、异常原因及历史依据必须保留。
